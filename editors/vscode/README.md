# Quarto-Needs for VS Code

This directory contains the **thin VS Code client** for the Quarto-Needs language server.

It does not parse `.qmd` engineering declarations, resolve relations, evaluate policies, compute coverage, or maintain an editor-specific engineering graph. Those responsibilities remain in the Python semantic core.

## Architecture

```text
VS Code document
      │
      ▼
vscode-languageclient
      │ stdio / LSP
      ▼
quarto-needs --root <workspace> lsp
      │
      ▼
Python parser + analyzer + LanguageService
```

The extension starts one language-server process per workspace folder containing `.quarto-needs.toml`. It also watches for that marker being created or removed after activation and starts/stops the corresponding client accordingly.

## Prerequisite

The Quarto-Needs Python package must be installed and its `quarto-needs` executable must be available to VS Code.

For a development checkout, install the Python project first:

```bash
python -m pip install -e .
```

If the executable is inside a virtual environment that VS Code does not inherit, configure `quartoNeeds.server.command` with the executable path. The extension itself never embeds a venv or machine-specific location.

## Development

```bash
cd editors/vscode
npm install
npm run check
npm run compile
```

A committed `package-lock.json` is intentionally expected before release-quality reproducible installs. It must be generated by npm from the real dependency graph; it must not be handwritten or inferred when the npm registry is unavailable.

## Package a VSIX

```bash
cd editors/vscode
npm install
npm run package
```

The package command compiles the extension through `vscode:prepublish` and writes:

```text
quarto-needs-vscode.vsix
```

`.vscodeignore` excludes TypeScript sources, source maps, build configuration, and development-only material while retaining the compiled extension and runtime dependencies required by `vscode-languageclient`.

## Install a local VSIX

From VS Code:

1. Open the Extensions view.
2. Choose **… → Install from VSIX…**.
3. Select `editors/vscode/quarto-needs-vscode.vsix`.
4. Open a workspace folder containing `.quarto-needs.toml`.

Or, with the VS Code CLI:

```bash
code --install-extension editors/vscode/quarto-needs-vscode.vsix
```

The extension should then start:

```text
quarto-needs --root <workspace-folder> lsp
```

for each Quarto-Needs workspace root.

## Server configuration

The command used to start the server is configurable as `quartoNeeds.server.command` and defaults to `quarto-needs`.

Additional server arguments can be supplied through `quartoNeeds.server.extraArgs`. They are inserted before the final `lsp` subcommand.

Example workspace setting:

```json
{
  "quartoNeeds.server.command": "/path/to/venv/bin/quarto-needs"
}
```

This path belongs to user/workspace configuration only; it is never committed into the extension implementation.

## Commands

- **Quarto-Needs: Restart Language Server**
- **Quarto-Needs: Show Language Server Output**

## Multi-root workspaces

Each workspace folder with `.quarto-needs.toml` receives its own language-server process and stable client identity derived from the workspace URI. A folder without the marker is ignored.

Adding or deleting `.quarto-needs.toml` after activation causes the client set to be synchronized automatically.

## Document selection

The client connects `.qmd` files recognized by VS Code as either `quarto` or `markdown`. All completion, diagnostics, hover, navigation, symbols, and rename behavior is provided by the Python LSP server.

## Architectural boundary

The TypeScript client must remain transport/presentation only. In particular it must not register its own completion, hover, definition, reference, rename, or diagnostic providers for Quarto-Needs semantics. Python regression tests enforce this boundary.
