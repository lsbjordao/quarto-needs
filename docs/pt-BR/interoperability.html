34  Interoperabilidade e Federação

Formatos de intercâmbio e integrações com serviços externos no Quarto-Needs são adaptadores e projeções sobre o grafo canônico de engenharia. Padrões externos transportam e federam requisitos sem comprometer a identidade ou a proveniência canônica.

34.1 Formatos Estruturados de Intercâmbio

34.1.1 ReqIF 1.2

Exporte o grafo de requisitos para ReqIF (Requirements Interchange Format) para troca de informações com ferramentas corporativas como IBM DOORS, PTC Integrity ou Polarion:

quarto-needs export --format reqif --output requirements.reqif

O exportador mapeia objetos de engenharia, atributos e relações canônicas para SpecObjects, SpecTypes e SpecRelations do padrão ReqIF.

34.1.2 JSON-LD 1.1

Exporte o grafo como Dados Conectados (Linked Data) preservando os metadados semânticos de relações:

quarto-needs export --format jsonld --output graph.jsonld

A projeção JSON-LD utiliza IRIs determinísticos, vocabulários de schema e mapeamento de contexto compatível com ferramentas da web semântica.

34.2 Federação Baseada em Padrões: OSLC RM

O Quarto-Needs oferece um adaptador somente-leitura com limites estritos para OSLC Requirements Management (RM):

pip install 'quarto-needs[oslc]'

As dependências opcionais fornecem normalização de JSON-LD, Turtle e RDF/XML. O CLI público expõe três operações:

  1. Inspeção de Catálogo: Lista URIs de Service Providers e de catálogos aninhados sem seguir esses catálogos:

    quarto-needs oslc catalog https://provider.example/oslc/catalog --format json

  2. Descoberta de Serviços: Inspeciona um Service Provider RM, suas capacidades de consulta e os Resource Shapes anunciados:

    quarto-needs oslc discover https://provider.example/oslc/sp/requirements --format json

  3. Capacidade de Consulta: Executa uma consulta HTTP GET delimitada no contexto de um Service Provider explícito (ou de um perfil configurado), sem realizar crawling recursivo de membros:

    quarto-needs oslc query https://provider.example/oslc/query/requirements \
  --service-provider-uri https://provider.example/oslc/sp/requirements

O resultado da consulta relata URIs de membros, nós já incluídos na resposta e o digest e timestamp de recuperação da resposta. O CLI não materializa observações independentes de requisitos nem as reconcilia com objetos locais.

Essas operações adicionais são APIs da biblioteca Python: quarto_needs.oslc_observe.materialize_query_observations() produz observações externas com proveniência individual, e quarto_needs.oslc_reconcile.reconcile_external_requirements() compara observações com objetos canônicos usando vínculos explícitos URI-para-ID. Elas exigem entradas fornecidas pelo chamador e não executam implicitamente após oslc query.

Credenciais são passadas com segurança via variáveis de ambiente:

export OSLC_TOKEN="..."
quarto-needs oslc discover https://provider.example/oslc/sp/requirements --bearer-token-env OSLC_TOKEN

A referência da linha de comando documenta perfis nomeados, comportamento do cache, limites de recuperação, busca opcional de shapes e todos os comandos públicos de OSLC. Também cobre as exportações JSON, CSV, SARIF, JUnit e Markdown usadas na automação.

34.3 Rastreadores Externos: GitHub Issues

O engine Python contém um adaptador somente-leitura para GitHub Issues com recuperação delimitada, proveniência, cache condicional, reconciliação e primitivas revisáveis de importação/aplicação. Esse adaptador é uma superfície de biblioteca/engine; ainda não existe um comando público quarto-needs github .... O comando separado github-report --git BASE..HEAD exibe uma projeção de mudanças locais no Git; não recupera issues.

O adaptador:

  • normaliza issues em envelopes de observação externa;
  • suporta paginação e cache condicional HTTP (If-None-Match / 304 Not Modified);
  • mantém o número da issue como dado externo, sem sobrescrever IDs canônicos;
  • exige revisão explícita antes de qualquer criação de requisito local.

Uma superfície própria de linha de comando fica adiada até que o fluxo público de autenticação e importação possa ser documentado e testado como contrato estável.
