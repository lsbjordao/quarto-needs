4  Requirements: refining the product obligations

The system requirements establish broad obligations. This chapter refines them into capabilities that can be implemented and quality constraints that shape how those capabilities must behave.

4.1 Functional requirements

FUN-001 · Parse engineering declarations from Quarto source

functional-requirement approved critical

Quarto-Needs shall parse .need declarations from QMD sources into structured engineering object declarations with stable identity and source locations.

Rationale

Text-first authoring is only useful if the semantic core can recover structured objects deterministically from ordinary documentation sources.

FUN-009 · Collapse the page margin TOC without obscuring navigation

functional-requirement approved medium

The HTML extension shall provide an optional persistent control that collapses and restores the page margin table of contents, reclaims content width while collapsed, and positions the expanded-state control entirely outside the TOC so it does not obscure the title or navigation items.

quarto toc sidebar usability progressive-enhancement

Rationale

A collapsible margin TOC is only useful if the control itself does not interfere with the navigation surface it manages. Its positioning is therefore treated as engineering behavior with an executable regression contract, not as incidental decorative styling.
