8  Interoperability: federating without surrendering the canonical model

Quarto-Needs treats interchange and federation as projections and adapters around the canonical engineering graph. External standards may transport, describe, or discover requirements, but they do not become a second semantic authority.

ADR-008 · Keep the first OSLC federation path read-only, bounded, and cache-provenanced

architecture-decision accepted 2026-08-30

Context and Problem Statement

OSLC introduces external identity, authentication, mutable remote representations, linked-data serialization, caching, query capabilities, and provider-specific failure modes. Treating those concerns as ordinary local objects or automatically traversing every discovered link would blur the trust boundary.

oslc federation read-only security

Decision Drivers

  • preserve the canonical Quarto-Needs graph as semantic authority;
  • make external identity and observed bytes independently auditable;
  • prevent hidden network activity during RDF normalization;
  • prevent credentials from crossing redirect origins or entering persistent artifacts;
  • support deterministic offline behavior without silently accepting stale state;
  • prevent discovery/query execution from becoming recursive Linked Data crawling;
  • distinguish query-container evidence from independently fetched member-resource evidence.

Decision Outcome

Implement OSLC as a read-only adapter. HTTP uses GET only with explicit budgets and same-origin redirects. Cached bytes are content-addressed by SHA-256 and historical observations are retained. RDF normalization performs no implicit remote context fetches. Query execution requires an explicitly selected query base, limits member count, and reports member URIs without recursively fetching them. A separate bounded observation step may fetch selected members individually and records provenance from each member’s actual representation bytes. Discovery, query results, member observations, Resource Shapes, and reconciliation inputs remain external projections and are not merged into the canonical graph.

Consequences

The adapter can discover, query, observe, and analyze reconciliation safely before synchronization exists. Canonical import and all remote writes remain deliberately deferred.

Confirmation

TC-015 exercises the complete network-free discovery orchestration path; TC-017 exercises bounded query execution and response provenance; TC-018 exercises independent member observation and per-resource provenance; TC-019 exercises the reviewed, non-mutating import-plan directives derived from that observation and reconciliation.

ADR-009 · Require explicit URI-to-canonical-ID bindings for OSLC reconciliation

architecture-decision accepted 2026-08-30

Context and Problem Statement

A remote OSLC requirement can expose an identifier or title that happens to match a local object even when the two resources are unrelated. Automatically treating such similarity as identity would permit silent aliasing across independent authorities.

oslc reconciliation identity conflict

Decision Drivers

  • preserve external resource URI as the primary remote identity;
  • make every bridge into canonical identity explicit and reviewable;
  • reject stale or rejected observations before reconciliation;
  • expose duplicate bindings and missing local targets as conflicts;
  • keep comparison separate from mutation.

Decision Outcome

Reconciliation is a pure analysis step. Only an explicit mapping from external resource URI to canonical Quarto-Needs ID can yield a matched item. External identifiers and titles are comparison data only. Unbound resources remain unbound, and field differences are reported without changing the snapshot.

Consequences

This is intentionally more conservative than heuristic import. A future import command may consume an accepted reconciliation plan, but it cannot infer identity by itself and it cannot bypass provenance/trust checks.

Confirmation

TC-016 proves that a matching external identifier alone remains unbound and therefore cannot create an implicit canonical identity.

ADR-010 · Keep the GitHub issues path read-only, bounded, and discovery-separated

architecture-decision accepted 2026-08-31

Context and Problem Statement

GitHub’s issues API returns pull requests alongside issues, rewrites pagination URLs from /repos/{owner}/{repo} to /repositories/{id} with cursor parameters, includes full inline issue data in list responses, and rate-limits clients with 403/429 responses. Treating any of those as canonical requirements data, following pagination without budgets, or flattening rate limits into generic errors would blur the trust boundary.

github federation read-only security

Decision Drivers

  • reuse OSLC’s source-agnostic identity, observation, reconciliation, and import-plan contracts instead of forking them;
  • keep discovered numbers separate from independently fetched, provenance-bound observations;
  • validate server-provided pagination targets by origin, never by path, because GitHub legitimately rewrites its own Link targets;
  • make truncation, malformed pagination, pull-request conflation, and rate-limit exhaustion explicit rather than guessed;
  • keep the transport free of retry policy: report the server’s retry facts and let the caller decide.

Decision Outcome

GitHub federation is a read-only adapter composed of a bounded JSON transport with rate-limit classification, an opt-in content-addressed cache with conditional requests, issue/projection normalization that rejects pull requests, discovery and bounded multi-page traversal that stay numbers-only, and reconciliation/import planning through the unchanged OSLC contracts. List data is never promoted into observations; pagination targets are origin-checked; rate limits raise a distinguished, retry-informing error.

Consequences

The adapter can discover, traverse, observe, reconcile, and plan imports safely before any synchronization exists. Canonical import and all remote writes remain deliberately deferred, and a rate-limit retry policy is caller-owned until a command needs one.

Confirmation

TC-020 exercises fetch-compose-normalize with exact-byte provenance; TC-021 exercises the conditional-request 304 reuse path; TC-022 exercises bounded traversal across GitHub’s rewritten pagination targets with honest truncation; TC-024 exercises rate-limit exhaustion classification against real header shapes.
